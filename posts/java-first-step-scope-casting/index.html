김영한의 자바 입문 - 스코프, 형변환

2026-11-10·6분 읽기

스코프

  • 변수는 선언 위치에 따라 지역 변수, 멤버 변수(클래스, 인스턴스의 변수)와 같이 분류된다.
  • 지역 변수(Local Variable)
    • 특정 지역에서만 사용할 수 있는 변수
    • 특정 지역을 벗어나면 사용할 수 없다.
      • 특정 지역이란 변수가 선언된 코드 블록({})을 의미한다.
    • 자신이 선언된 코드 블록({}) 안에서만 생존하고, 해당 블록을 벗어나면 제거된다. 이후에는 접근할 수 없다.
  • 이렇게 변수의 접근 가능한 범위를 스코프(Scope) 라고 한다.

스코프의 존재 이유

  • 위 코드는 if 조건에 따라 변수 m을 2배 증가시켜 출력하는 코드이다.
  • 임시 변수 temp를 사용했지만, temp는 if 조건이 만족할 때 임시로 사용하는 변수이다.
  • 그런데 temp는 main() 블록 안에 선언되어 있다. 이에 따라 다음과 같은 문제가 발생할 수 있다.
    • 비효율적인 메모리 사용
      • temp는 if 안에서만 사용되지만, main() 블록이 종료될 때 까지 메모리에 유지된다.
      • if 안에 temp를 선언했다면 자바를 구현하는 곳에서 if 코드 블록 종료 시점에 temp를 메모리에서 제거하여 더 효율적인 메모리 사용이 가능하다.
    • 코드 복잡성 증가
      • temp는 if 안에서만 필요하기 때문에 그 안에서만 사용하면 된다.
      • if가 끝나도 main에서 temp에 접근할 수 있기 때문에 누군가 이 코드를 유지보수 할 때 m은 물론이고 temp도 신경써야 한다.

for vs whlie 스코프를 통해 생각해보기

  • while 문의 경우 변수 i의 스코프가 main() 전체가 된다.
  • for 문의 경우 변수 i의 스코프가 for 문 안으로 한정된다.
  • 따라서 변수 i처럼 for 문 안에서만 사용되는 변수가 있다면 while 문 보다는 for 문을 사용하여 스코프의 범위를 제한하는 것이 메모리 사용과 유지보수 측면에서 더 좋다.

형변환

자동 형변환

  • 작은 범위 → 큰 범위로는 값을 넣을 수 있다.

    • int → long → double

  • 큰 범위에서 작은 범위는 문제가 발생할 수 있다.

    • 오버플로우
    • 소수점 버림

  • 작은 범위 → 큰 범위로 대입은 허용한다.

  • 자바의 숫자 표현 범위

    • int < long < double

  • 자바는 기본적으로 같은 타입에 값을 대입 가능

  • 다른 타입에 값을 대입하면...

    • int → long
      • long이 int보다 더 큰 숫자 범위를 표현
      • 작은 범위 숫자 타입에서 큰 범위 숫자 타입에 대입하는 경우이므로, 문제가 되지 않음
    • long → double
      • double이 부동소수점을 사용하기 때문에 더 큰 숫자 범위를 표현함, 문제가 되지 않음
    • 자바에서 작은 범위 타입에서 큰 범위 타입으로의 대입은 허용된다.
    • 하지만 결국 대입하는 타입을 맞추어야 하기 때문에 개념적으로는 아래와 같이 동작한다.
    • 위 처럼 값 앞에 (double) 과 같이 타입을 적어주면 int 타입이 double 타입으로 변한다. 이를 형변환이라고 한다.
    • 작은 범위 숫자 타입에서 큰 범위 숫자 타입으로의 형변환은 개발자가 직접 하지 않아도 된다.
    • 자동으로 일어나기 때문에 자동 형변환, 또는 묵시적 형변환 이라고 한다.

명시적 형변환

  • 반대로 큰 범위 → 작은 범위로 대입에는 명시적 형변환이 필요하다.

  • double 은 실수를 표현할 수 있다. 따라서 1.5를 double 타입으로 표현하는 것은 가능하다.

  • 그러나 int 는 실수를 표현할 수 없다. 따라서 int 타입에 double 타입을 대입하게 되면 1.5에서 .5를 표현할 수 없게 된다.

  • 그러나 이런 위험을 알고도 값을 대입하고 싶다면, 데이터 타입을 강제로 변환할 수 있다. 이것을 형변환(Casting)이라고 한다.

  • 그리고 개발자가 직접 형변환 코드를 입력한다고 해서 명시적 형변환이라고 한다.

  • 개념적인 동작 과정은 아래와 같다.

  • 형변환을 한다고 해서 doubleValue의 타입이 변경되거나, 그 안에 있는 값이 변경되는 것은 아니다. doubleValue에서 읽은 값을 형변환 하는 것이다.

  • doubleValue 안에 들어있는 값은 1.5 그대로 유지된다.

형변환과 오버플로우

  • 정상 범위

    • long maxIntValue = 2147483647;는 int의 가장 큰 숫자를 입력했다.
    • 이 경우 int 로 표현할 수 있는 범위에 포함되기에 long → int 형변환이 문제가 없다.

  • 초과 범위

    • long maxIntOver = 2147483648L;는 int의 가장 큰 숫자(2147483647)보다 1 큰 숫자를 입력했다.
    • 이 경우 리터럴은 int 범위를 넘어가기 때문에 L을 붙여 long 타입을 사용해야 한다.
    • 또한 위처럼 long → int 형변환에서 문제가 생긴다.
    • 결과는 -2147483648 이라는 값이 나온다.
      • -2147483648는 int가 표현할 수 있는 가장 작은 숫자이다.
    • 이렇게 기존 범위를 초과하여 표현하게 되면 전혀 다른 숫자가 표현되는 현상을 오버플로우 라고 한다.
      • 오버플로우가 발생하면 시계가 한 바퀴 돈 듯이 처음부터 시작한다.
    • 오버플로우가 발생하는 것 자체가 문제이며 우리는 오버플로우가 발생하지 않도록 막아야 한다.
    • 이런 경우 int → long 으로 변경하여 사이즈를 늘리면 문제가 해결된다.
