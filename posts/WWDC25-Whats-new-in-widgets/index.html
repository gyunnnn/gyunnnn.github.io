[WWDC25] What's new in widgets

2025-12-30·9 min read
WWDC25SwiftUIWidget

기존 플랫폼에서의 위젯 개선 (iOS, macOS)

  • iOS 26 홈 화면에서 위젯을 투명 모드 / 틴트 모드로 설정 가능 (사용자화)

Accented rendering mode

원본 위젯

widgetRenderingMode가 Accented가 되어 모든 컨텐츠를 흰색으로 채색한 모습

background가 제거되고 투명 상태 혹은 tint color로 대체됨

  • 위젯 콘텐츠는 Accented Rendering Mode로 생성되어 모든 내용이 흰색으로 채색됨
  • 위젯 백그라운드가 제거되고, 투명 유리 / tint color로 대체됨
  • accented 모드에서 아무것도 하지 않아도 알아서 변경됨

이미지, 그라디언트, 텍스트로 이루어진 원본 위젯

accented 모드가 되어 모든 컨텐츠가 흰색으로 표시됨. 라떼 컵 처럼 불투명한 객체는 모두 흰색으로 표시됨. 그라디언트와 같이 일부가 투명한 컨텐츠는 불투명도를 유지하며 흰색으로 색조가 입혀짐

  • 문제 상황
    • 카페인 트래킹 앱 위젯의 이미지 위에 텍스트를 두어 가독성을 높였으나, accented rendering시 문제가 발생함
      • accented rendering mode 적용시, 불투명한 객체(ex: 라떼 컵)는 모두 흰 색으로 표시됨
      • 투명한 내용물(ex: 그라데이션)은 불투명도를 유지하며 흰색으로 색조가 입혀짐
      • 이미지가 원하는 모습이 아니며, 텍스트 가독성이 떨어짐
  • 해결 방법
    1. 위젯이 .fullColor 로 렌더링되는 경우에만 큰 이미지와 선형 그라데이션을 조건부로 나타내도록 설정
    2. VStack 을 추가하고, 위젯이 accented 모드일 때 이미지를 조건부로 표시하도록 설정한 후 이미지를 가져옴

WidgetRenderingMode Modifier를 통한 이미지 제어

  • accented mode에서 이미지의 모습을 개선하기 위해 widgetAccentedRenderingMode 를 이미지에 적용
  • 이 modifier는 accented mode에서 이미지가 어떻게 보일지 제어하며, 5가지 옵션이 주어짐

  • nil
    • modifier를 사용하지 않는 것과 같음
    • image에 primary content color를 적용함
    • iOS, watchOS 위젯에서는 이미지를 완전히 흰색으로 만듬

  • .accented
    • accent color를 전달하면 이미지가 accentColor 색상으로 변함
    • iOS, macOS에서는, primary color와 accentColor가 모두 흰색이므로 이미지도 흰색으로 변함
    • watchOS에서 accentColor는 watch face의 색상과 일치함

  • .desaturated
    • 이미지 색상 채도가 낮아짐
    • iOS, watchOS 프레젠테이션 스타일 모두에서 동일하게 보임

  • .accentedDesaturated
    • .accented, .desaturated 모두 적용됨
    • 이미지 색상의 채도가 낮아지며, 선택한 테마의 accentColor가 적용됨
    • iOS에서는, 이미지가 약간 더 하얗게 변화하고, watchOS에서는, 채도 낮은 이미지가 테마의 accentColor로 변경됨

  • .fullColor
    • accented rendering mode에서 수정되지 않은 원본 이미지가 표시됨
    • watchOS에서는 무시됨(watch face와 잘 어울려야 하기 위함)
    • 앨범 아트워크, 책 표지 등 미디어 콘텐츠를 나타내는 이미지에는 fullColor를 사용

정리

  • 대부분의 위젯
    • .desaturated, .accentedDesaturated를 사용하여 이미지 콘텐츠가 홈 화면과 조화를 이루도록 함
  • 미디어 콘텐츠(앨범 아트워크, 책 표지 등)를 나타내는 이미지를 포함한 위젯
    • .fullColor를 사용

새로운 플랫폼에서의 위젯 활용

VisionOS에서의 위젯 활용

  • VisionOS 26부터 VisionOS 앱에서 위젯 사용이 가능
  • 호환되는 iPhone/iPad 앱이 있다면 해당 앱의 위젯이 VisionOS에서 자동으로 사용 가능
  • iOS 및 macOS의 모든 System family sizes가 지원됨
  • Interaction, animation 지원

표면 고정 및 스타일링

  • 위젯을 방의 표면에 추가하여 고정할 수 있음
  • 기본적으로 표면 위에 떠 있는 모습(floating)
  • 임베딩 스타일
    • 오목하게 만들어 표면에 임베드된 것 처럼 보이게 할 수도 있음
    • WidgetConfiguration에서 supportedMountingStyles 를 사용하여 적용할 옵션을 명시 가능
      • VisionOS, iOS에서 사용 가능 (26+)

Texture 적용

  • 기본적으로 위젯은 glass texture 아래에 렌더링 됨. (좌측)
  • WidgetConfiguration에서 widgetTexture 를 사용하여 다른 종이 질감을 명시 가능 (우측)

새로운 Widget Family 및 테마

  • systemExtraLargePortrait
    • VisionOS에서 기존 systemExtraLarge 가로 위젯의 세로 버전이 새롭게 제공
    • supportedFamilies 를 통해 WidgetConfiguration에 추가 가능

  • VisionOS에서는, 위젯의 color theme을 설정할 수 있음
    • 기본값은 fullColor presentation
    • 초록색 theme 선택 시, 위젯 프레임과 콘텐츠는 선택한 theme 색상으로 변경, 백그라운드는 제거된 후 선택한 theme 색상을 보완하는 단일 색상으로 대체됨
    • iOS, macOS와 동일한 렌더링 방법을 적용
    • 이미지 노출 방식은 .widgetAccentedRendringMode 와 widgetRenderingMode 환경변수를 사용하여 결정

거리 기반 적응(LevelOfDetail API)

  • VisionOS 위젯은 여러 표면에 위치시킬 수 있으며, 다른 공간으로 이동해도 고정된 위치에 유지됨.
  • 실제 물리적 객체와 달리, VisionOS 위젯은 멀리 있을 때 LevelOfDetail API를 사용하여 거리에 따라 변화할 수 있음
  • @Environment(\.levelOfDetail)
    • .default: 위젯에 일반적인 수준의 세부 정보를 표시
    • .simplified: 물리적으로 멀리 있을 때, 세부 정보를 간소화하여 더 단순하고 쉽게 볼 수 있음

  • 구현 예시
    • 멀리 있을 때 총 카페인 값을 더 크게 표시, 버튼은 숨김
    • LogDrinkView 를 LevelOfDetail 값이 .default인 경우에만 표시되도록 설정
    • TotalCaffeineView 에는 LevelOfDetail 환경변수를 추가하여, 정보 수준에 기반해 폰트 크기를 조건부로 크게 만듬.

  • 결과
    • 위젯이 멀리 있을 때 간결해지며, 세부 정보 수준 변화엔는 애니메이션 효과 적용

CarPlay에서의 위젯 및 Live Activities

1. CarPlay Ultra의 위젯

  • 위젯은 대시보드 왼 쪽에 있는 하나 이상의 스택에 나타나며, iOS 26부터 CarPlay 탑재 차량에서 활용 가능
    • 설정 앱에서 구성 가능
    • CarPlay 위젯은 StandBy 스타일로 렌더링됨
      • 차량 디스플레이에서 읽기 쉽도록 한 눈에 들어오는 정보, 큰 폰트, 가독성이 중요하기 때문
      • 이를 지원하기 위해 CarPlay는 위젯 백그라운드를 제거한 fullColor의 systemSmall family 위젯을 사용하여 위젯을 렌더링함
    • 터치스크린을 통해 상호작용 할 수 있음
    • StandBy Presentation에 맞게 위젯을 조정하려면, WWDC 23 - Bring Widgets to new places 참고

2. CarPlay에서의 Live Activities

  • 홈 화면에도 표시될 수 있으며, 기본적으로 iPhone의 Dynamic Island Leading View 및 Trailing View가 표시됨

3. Live Activities Presentation 커스텀

  • supplementalActivityFamilies modifier를 추가하고, .small 을 인자로 넘기면, Leading, Trailing View 대신, Activity View가 표시됨
    • 이 뷰는 iOS 잠금화면에 사용 되는 것과 동일
    • 일부 내용이 끊겨 비좁아 보일 경우 추가 작업이 필요할 수도 있음
  • activityFamily 환경 변수 추가
    • activityFamily 가 .small인 경우, 작은 레이아웃에 최적화된 OrderView를 제공, 그렇지 않은 경우, 기본 ShopOrderView 제공

4. Apple Watch 연동 효과

  • supplementalActivityFamily 를 사용하게 되면, Apple Watch와 페어링되어 표시될 때 Live Activities가 더 잘 나타나게 되며, iPhone 앱에도 자동으로 표시됨 (별도 watchOS 앱 불필요)
  • WatchOS 스마트 스택에서의 최적화 방법

    • https://developer.apple.com/videos/play/wwdc2025/216/

  • 해결책

Relevance Widget Configuration

  • type
    • **RelevanceConfiguration**으로 위젯을 생성

  • Provider
    • RelevanceEntriesProvider
    • 아래 두 메서드는 TimelineEntriesProvider와 유사함
  • placeholder()
    • 위젯 콘텐츠 준비 중 표시할 간단한 항목을 리턴함 (TimelineEntriesProvider와 유사)
  • relevance()
    • 해피아워 위젯의 경우, 시작/종료시간을 기준으로 relevance를 구성해야 하며, 각 해피아워의 interval 을 사용하여 설정함
  • entry()
    • TimelineEntriesProvider 와는 다르게, 하나의 Entry를 리턴함
      • configuration에 필요한 모든 정보가 Entry에 포함됨
        • ex: shop, timeRange
        • 비동기(async) 메서드이므로 다른 데이터나 에셋을 가져올 수 있음

  • Relevance Widget의 여러 Configuration이 존재하는 경우, 스마트 스택에서 여러 인스턴스를 볼 수 있음

Push widget updates

예약된 위젯 리로딩(Scheduled widget reloads)

  1. 위젯이나 watch face가 설정되면, WidgetKit은 Widget Extension에게 Timeline을 요청함
  2. Extension은 TimelineReloadPolicy가 포함된 Widget Timeline으로 응답
  3. WidgetKit은 해당 Widget을 Reload할 적절한 시간을 결정함
  • TimelineReloadPolicy는 일정한 간격으로 업데이트가 필요한 위젯(카페 운영 시간, 날씨, 주식 등)에 사용하기 좋음
  • 예산 책정
    • 예정된 Timeline 리로딩 시, 성능과 배터리 유지를 위해 시스템이 리로드에 대한 budget을 책정함

명시적 위젯 리로드(Explicit widget reloads)

  1. 앱 내에서 위젯에 반영될 데이터 변경(ex. 카페인 기록 업데이트, 메모 변경, 미리 알림 체크 등)이 발생했을 때 훌륭한 옵션
  2. WidgetCenter API의 reloadAllTimelines 또는 reloadTimelines(ofKind:) 메서드 호출
  3. WidgetKit에 위젯 콘텐츠가 오래되어 다시 로드해야 함을 알려주면, WidgetKit이 Extension에 Timeline을 요청해 위젯을 업데이트함
  4. API 호출 시 앱이 실행중이므로 시스템이 요청의 budget을 책정하지 않음

위젯 푸시 업데이트(Widget push update)

  1. 서버나 다른 기기에서 데이터가 변경될 때 유용함
  2. 원리
    1. 데이터 변경 추적 서버는 APNS(Apple Push Notification Service)에 푸시 알림을 보내 WidgetKit에게 해당 앱의 위젯을 다시 로드하라고 전달함
    2. WidgetKit은 업데이트된 Timeline을 요청
  3. TimelineReloadPolicy와 동일하게, 위젯 푸시 알림 업데이트도 성능 및 배터리 수명 유지를 위해 budget이 책정됨
  4. 이 옵션들은 상호 배타적이지 않으며, 여러 선택지를 위해 함께 사용할 수 있음
    • 위젯 푸시 업데이트를 사용하면 iPad 앱, Vision Pro 위젯, macOS Menu Bar Controls 등 어디서 업데이트하던지 정보를 최신 상태로 유지할 수 있음

위젯 푸시 업데이트 구현

구현 단계

  1. WidgetPushHandler 생성 및 추가
  2. Widget Extension에 Push Notification entitlement 추가
  3. 위젯 업데이트 푸시 request 구성

  • WidgetPushHandler를 따르는 구조체 생성
    • push token 변경이나, 구성된 위젯 세트 변경시 알림을 보냄
    • pushTokenDidChange 메서드를 통해 서버에 푸시 토큰과 위젯 정보를 보냄

  • Widget Configuration 수정
    • .pushHandler() modifier를 추가하여 push notification 지원을 등록함
    • 해당 modifier에는 앞서 구현한 WidgetPushHandler 타입을 전달해야 함

  • Xcode에서 Widget Extension의 Signing & Capabilities 탭에서 Push Notification Entitlement를 추가하여 APNS와 통신할 수 있도록 설정함

  • 위젯 업데이트 푸시 노티를 보내는 방법

  • HTTP Method는 POST

  • WidgetPushHandler에 제공된 Widget Push Token을 path의 마지막 부분으로 사용

  • 헤더

    • apns-topic 헤더에는 앱의 번들ID를 사용
    • apns-push-type 헤더에는 widgets 입력

  • body

    • aps dictionary → content-changed를 true로 변경

  • 위젯 업데이트 푸시 기능은 위젯 콘텐츠를 보다 최신 상태로 유지하는 데 도움이 되지만, 필요할 때마다 수행되며 다른 Notification 경험을 직접 대체하지는 않음

    • 긴급/중요 업데이트
      • User Notification 사용
    • 한정된 시간의 정기적 업데이트
      • Live Activity
      • 예) 음료 주문, 스포츠 경기 점수 업데이트, 비행편 업데이트
    • 위젯 콘텐트의 최신 상태 유지
      • Widget push updates

  • Widget push updates의 플랫폼 호환

    • 모든 위젯 지원 플랫폼에서 사용됨
    • 푸시 알림을 보내면 디바이스에 구성된 모든 push 가능 위젯이 업데이트됨
    • 위젯 리로딩에는 budget이 책정되므로, 업데이트 푸시를 제한해야 함
      • 예) 서버에서 업데이트에 스로틀링 적용
      • 개발 및 테스트 단계에서는 Settings에서 WidgetKit Developer Mode를 사용하여 푸시를 무시하고 앱의 budget을 다시 로드할 수 있음
